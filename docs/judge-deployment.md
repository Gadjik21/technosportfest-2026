# Отдельная песочница для программных задач

`compose.judge.yaml` добавляет к обычному стеку один обработчик очереди. Он забирает решения из PostgreSQL по одному и запускает **отдельный одноразовый контейнер для каждого теста**. API не получает доступ к Docker. У каждого теста отключена сеть, удалены привилегии, ограничены память, процессы и время; код из разных тестов не разделяет запущенный контейнер.

## Подготовка Linux-сервера

Нужен отдельный непривилегированный пользователь только для песочницы и его собственный Docker Engine в rootless-режиме. Основной Docker-сокет `/var/run/docker.sock` сюда не подключается. Rootless Docker требует `newuidmap`, `newgidmap`, диапазоны subordinate UID/GID, systemd и cgroup v2 с драйвером `systemd`; иначе лимиты памяти и процессов могут игнорироваться. [Инструкция Docker по rootless-режиму](https://docs.docker.com/engine/security/rootless/) и [ограничения ресурсов](https://docs.docker.com/engine/security/rootless/tips/#limiting-resources) описывают эти условия.

1. Создайте отдельного системного пользователя, например `tsf-judge`. Установите для него rootless Docker штатной командой `dockerd-rootless-setuptool.sh install` и включите user service + lingering, как в документации Docker. У этого пользователя не должно быть доступа к основному Docker-сокету, проекту, ключам деплоя или другим данным сервера.
2. Создайте рабочий каталог, принадлежащий этому пользователю, например `/srv/tsf-judge/work`. Каталог должен быть доступен **по тому же абсолютному пути** как основному Docker Compose, так и rootless-демону.
3. От имени этого пользователя укажите `DOCKER_HOST=unix:///run/user/<UID>/docker.sock` и выполните `tools/judge-images.sh` из репозитория. Скрипт проверит rootless/cgroup и заранее загрузит образы Python, Node.js и Go.
4. Скопируйте `judge.env.example` в `.env.judge` и укажите UID, GID, путь к отдельному rootless-сокету и каталогу. Файл `.env.judge` игнорируется Git.
5. Выполните `make judge-up`. Команда собирает API, сайт и обработчик, поднимает PostgreSQL и ждёт здоровья сервисов. На 2-ГБ сервере запускайте только один обработчик. Для остановки без удаления базы — `make judge-down`.

`JUDGE_ENABLED` и адрес внутреннего health-check устанавливаются только в дополнительном Compose-файле. Если обработчик недоступен, API не публикует соревнование с программными задачами и не принимает новый код. Обычный `make up` оставляет проверку кода выключенной. Сейчас поддерживаются Python, Node.js и Go. Параметры задачи: по умолчанию 15 секунд и 128 МиБ на тест, верхний предел памяти 512 МиБ. Компиляция Go выполняется отдельно с лимитом 512 МиБ и 60 секунд.

Время исполнения и наблюдаемый пик памяти записываются для решения. Очень короткий процесс может завершиться до первого замера Docker; в этом случае память остаётся пустой, а не показывается как ноль.

На macOS Docker Desktop не является отдельным rootless-демоном, поэтому `make judge-up` намеренно не включает песочницу через его основной сокет. На Mac можно проверить тесты, сборку Compose и сам исполнитель на доверенных примерах. Полный запуск через `make judge-up` проверяется на Linux-сервере после выдачи доступа.
